# 起動済みプロファイルへのフォーカス機能の改善計画

既に起動しているChromeプロファイルを選択した際、既存のウィンドウにフォーカスが当たらず新しいウィンドウが開いてしまう問題（Issue #2）を解決するための計画です。

## 調査フェーズ（原因解析）の結果
実機環境での詳細なデバッグログ解析および外部スクリプトの検証により、以下の問題が特定されました。

### 1. 初期の解析結果（問題1〜5）
- **Defaultプロセスの誤検知**: 引数を持たない他アプリのChromeプロセスをDefaultと誤認していた。
- **引数形式の曖昧さ**: クォーテーションの有無（`--profile-directory=Default` など）で一致しなくなる。
- **タイトル依存の脆弱性**: ロジックがウィンドウ正規タイトルに依存していた。
- **WMIの遅延**: 全プロセスを都度走査するため、クリックごとに数秒の遅延が発生していた。
- **モデルの未使用プロパティ**: `ProfileInfo.Hwnd` 等が定義されているが、活用されていなかった。

### 2. プロセスの集約問題（問題6：最新の発見）
- **現象**: 複数のプロファイルを同時に開いている場合、Chrome はすべてのウィンドウを一つのプロセス（主に最初に開いたプロファイルの PID）に集約してしまう。
- **実態**: OS（WMI）から見ると、すべての Chrome プロセスの引数が `--profile-directory="Default"` になっている場合があり、`Profile 1` 以降のウィンドウが「プロセス引数検索」だけでは絶対に見つからない状態が発生していた。

## 参考：AutoHotkey (AHK) スクリプトによる実装アプローチ
調査の過程で検討された AHK スクリプトでは、プロセスの引数に頼らない以下の「差分検知方式」が採用されていました。

### 仕組み：スナップショットと新規ウィンドウの待機
1.  **起動前のスナップショット**: Chrome を起動する直前に、現在システム上に存在するすべての Chrome ウィンドウ (`ahk_class Chrome_WidgetWin_1`) の `hwnd` 一覧を取得して保存する。
2.  **プロファイルの起動**: `--profile-directory` 引数を付けて Chrome を実行する。
3.  **差分のポーリング**: 起動後数秒間、一定間隔で「現在のウィンドウ一覧」を監視し、**「1のスナップショットに含まれていなかった新しい `hwnd`」**が出現するのを待つ。
4.  **自動紐付け**: 新しく発見された `hwnd` を、今起動したプロファイルのものとしてメモリ上にキャッシュする。

### 本プロジェクトへの示唆
- **メリット**: プロセスが集約されて引数が取れなくなっても、起動した瞬間の「増分」を見ることで確実に特定できる。
- **デメリット**: ランチャ起動前から開いているウィンドウの特定ができない。
- **採用方針**: 私たちのメインロジック（AUMID/タイトル方式）で既存ウィンドウが見つからない場合に、新規起動時の特定精度を高めるための補助ロジックとして参考にします。

## 設計・実現性調査フェーズ（対応方針決定）
調査結果に基づき、以下の重層的な対応方針を採用します。

### 基本方針（対応1〜6）
- **正規表現の導入**: クォーテーションの有無を吸収し、プロファイルIDを正確に抽出。
- **クラス名判定**: `Chrome_WidgetWin_1` を取得条件に加え、判定を安定化。
- **Default判定の厳格化**: `--user-data-dir` の有無等を確認し、意図しないプロセスを除外。
- **フォーカス制御の強化**: `AttachThreadInput` を使用し、Windowsの制限を回避して確実に前面へ。
- **パフォーマンス改善**: PIDフィルタリングによるWMIクエリの高速化。
- **ハイブリッドキャッシュ（方式C）**: メモリ上に `IntPtr` (HWND) を保持し、2回目以降は検証のみで即座にフォーカス。

### 進化版・特定ロジック（対応7：多層フィルタリング）
プロセス集約問題を解決するため、ウィンドウの特定を以下の優先順位（スコアリング）で行います。

1.  **AppUserModelId (AUMID) マッチ（最優先）**:
    Windowsのアイコン分離に使用される `SHGetPropertyStoreForWindow` を介して AUMID を取得。これが `Chrome.Relinquished.[プロパティID]` 形式で各ウィンドウに割り当てられているため、プロセス引数に関わらず確実に特定可能。
2.  **ウィンドウタイトルマッチ（補完）**:
    タイトルにプロファイルの表示名（例：`健一`, `CoderDojo`）が含まれているかを確認。
3.  **コマンドライン引数マッチ（レガシー）**:
    従来通りプロセスの引数も確認し、情報の確度を補完する。
