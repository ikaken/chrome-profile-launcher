# Chromeプロファイルランチャ仕様書（WPFネイティブ版・最終）

---

## 1. 概要

本仕様は、Google Chromeの複数プロファイルを効率的に管理・切替するためのWindowsネイティブランチャアプリの設計を定義する。

実装は C#（.NET）および WPF を使用する。

---

## 2. 目的

- ワンクリックでプロファイルを起動・切替
- 起動済みプロファイルの即時フォーカス
- プロファイル情報の自動取得と管理
- 軽量・高速・配布容易なアプリの実現

---

1. Google Profile Picture.png
2. Google Profile.ico（上記PNGがない場合）

### 4.4 ランチャ機能

#### 動作
- 起動済 → フォーカス
- 未起動 → 起動

#### 起動コマンド
```
chrome.exe --profile-directory="Profile X"
```

---

### 4.5 起動状態判定（改良）

#### 方法
- **LOCK判定**: 各プロファイルディレクトリ内の `SingletonLock` ファイルの有無をOSレベルで確認し、起動状態を一次判定する。
- **ウィンドウ・プロセス差分検出**: 起動直前と直後のスナップショットを比較し、新規に増えたウィンドウ/プロセスを当該プロファイルに紐付ける。これにより、Chromeのプロセス集約問題（既存プロセスへの吸収）が発生しても確実に特定が可能。
- **動的生存監視**: 紐付けられたウィンドウハンドル（hwnd）の有効性を定期的に確認し、終了を検知する。

---

### 4.6 フォーカス制御

- Win32 API (`SetForegroundWindow`, `ShowWindow`)
- **確実な最前面化**: `ShowWindow(SW_RESTORE)` で最小化を解除した後、`AttachThreadInput` を用いてフォアグラウンドスレッドにアタッチし、Windowsの制限を回避して確実にウィンドウを前面へ移動させる。
- **ウィンドウクラス名判定**: `Chrome_WidgetWin_1` およびプロセス名 `chrome` を確認し、Electron系アプリ（Slack、VS Code、Discord等）が同一クラス名を使用する問題を回避。

---

### 4.7 設定機能

- 並び替え（ドラッグハンドルを使用した直感的なドラッグ＆ドロップ）
- 表示／非表示（トグルスイッチによる切り替え）
- プロファイルフォルダ名を表示（プロファイル名の下に表示）
- プロファイルフォルダを開く機能（「OPEN」ボタン）
- ※プロファイル名およびアイコンの編集機能（独自の画像指定など）は提供しない

---

### 4.8 ウィンドウ位置・サイズの記憶・復元

#### 保存タイミング・条件
- アプリケーション終了時（ウィンドウクローズ時）にウィンドウの位置とサイズを設定ファイルに保存する。
- **通常状態（`WindowState.Normal`）の場合のみ保存する**。最大化・最小化状態で閉じた場合は保存しない（前回の通常状態の値を維持する）。
- **保存処理の独立性**: ウィンドウ位置の保存とプロファイル設定の保存は互いに独立した操作とし、一方の保存が他方のデータを上書き・消失させないこと。

#### 保存データ
| フィールド | 型 | 説明 |
|---|---|---|
| `WindowLeft` | `double?` | ウィンドウの左端X座標。`null` = 未保存（初回起動時）。 |
| `WindowTop` | `double?` | ウィンドウの上端Y座標。`null` = 未保存。 |
| `WindowWidth` | `double?` | ウィンドウの幅。`null` = 未保存。 |
| `WindowHeight` | `double?` | ウィンドウの高さ。`null` = 未保存。 |

#### 復元ルール
- 次回起動時に保存された位置・サイズでウィンドウを復元する。
- **初回起動時**（保存データが `null` の場合）: 画面中央に配置し、デフォルトサイズ（420×500）で表示する。

#### 復元の安全策（フォールバック条件）
以下のいずれかに該当する場合は、画面中央配置・デフォルトサイズにフォールバックする：
1. 保存された座標が仮想スクリーン境界の完全に外にある場合（ウィンドウの端が1pxでも画面内に入っていれば許容する。DPI設定の変更やモニター構成変更で座標が範囲外になるケースをカバーする）
2. 保存されたサイズが最小閾値未満の場合（最小幅: 200px、最小高さ: 150px）

※「画面中央配置」とは、プライマリモニターの中央に配置することを指す。

---

### 4.9 単一インスタンス制御（二重起動防止）

- **動作**: アプリケーションの同時起動を1つに制限する。
- **仕組み**: 名前付き `Mutex` を使用して二重起動を検知する。
- **二重起動時の振る舞い**: 
  - 既に起動しているアプリケーションのメインウィンドウを探索し、最前面（フォアグラウンド）に表示する。
  - 既存ウィンドウが最小化されている場合は、元のサイズに戻してから前面に出す。
  - 後から起動しようとしたプロセスは、既存ウィンドウの活性化後に即座に終了する。

## 6. データ設計

### 設定ファイル

```json
{
  "Profiles": [
    {
      "Id": "Default",
      "DisplayName": "仕事用",
      "IsVisible": true,
      "Order": 0,
      "IconPath": "C:\\Users\\...\\Google Profile Picture.png"
    },
    {
      "Id": "Profile 1",
      "DisplayName": "個人",
      "IsVisible": true,
      "Order": 1,
      "IconPath": ""
    }
  ],
  "WindowLeft": 100.0,
  "WindowTop": 100.0,
  "WindowWidth": 420.0,
  "WindowHeight": 500.0
}
```

> **注記**: `System.Text.Json` のデフォルト設定を使用するため、JSONのプロパティ名はC#のプロパティ名（PascalCase）と一致する。`WindowLeft` 等のウィンドウ位置フィールドは未実装のため、現在の設定ファイルには含まれない。

### 保存場所

```
%AppData%\\ChromeProfileLauncher\\settings.json
```

## 7. 処理フロー

### 起動時
1. プロファイル取得
2. 設定読込
3. データマージ（Chrome側プロファイルをベースとし、設定があれば上書き、なければデフォルト追加）
4. アイコンキャッシュ確認
5. UI生成

### 操作時
1. **状態確認**: `SingletonLock` の存在を確認。
2. **フォーカス**: 起動中の場合、管理下の `hwnd` が有効であればフォーカス。無効であればタイトルマッチ等で再探索してフォーカス。
3. **バックアップ**: ウィンドウが見つからない場合は「未起動」として扱う。
4. **起動**: プロセス起動直前にウィンドウ一覧のスナップショットを取得。
5. **プロセス実行**: `--profile-directory` 指定での起動。
6. **紐付け**: 出現した新規ウィンドウ/プロセスを `hwnd` として記録。

## 13. 制約

- **Chrome仕様依存**: LOCKファイルの存在、プロセス集約の挙動、ウィンドウクラス名 (`Chrome_WidgetWin_1`) など、Chromeの内部実装に依存する。アップデートにより変更される可能性がある。
- **外部起動の制限**: ランチャ外から起動されたプロファイルウィンドウは、差分検出では捕捉できない（タイトルマッチでのフォールバックは可能）。
- **AUMIDの制限**: AppUserModelId (AUMID) は全プロファイルで共通のため、プロファイル識別には使用不可。ただし、非Chromeウィンドウ（Electron系アプリ等）の除外フィルタとしては活用可能。現在の実装では、AUMID の代わりにウィンドウクラス名 + プロセス名チェックで同等のフィルタリングを実現している。
