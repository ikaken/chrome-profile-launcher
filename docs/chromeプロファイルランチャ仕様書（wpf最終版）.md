# Chromeプロファイルランチャ仕様書（WPFネイティブ版・最終）

---

## 1. 概要

本仕様は、Google Chromeの複数プロファイルを効率的に管理・切替するためのWindowsネイティブランチャアプリの設計を定義する。

実装は C#（.NET）および WPF を使用する。

---

## 2. 目的

- ワンクリックでプロファイルを起動・切替
- 起動済みプロファイルの即時フォーカス
- プロファイル情報の自動取得と管理
- 軽量・高速・配布容易なアプリの実現

---

## 4. 機能要件（詳細）

### 4.1 プロファイル一覧取得

#### 入力
```
%LOCALAPPDATA%\\Google\\Chrome\\User Data
```

#### 処理
1. ディレクトリ走査
2. Default / Profile X 抽出
3. 不要フォルダ除外

#### エラー処理
- 存在しない場合はスキップ
- アクセス拒否は無視

---

### 4.2 プロファイル情報取得

#### ファイル
```
Local State
```

#### 処理
- JSON解析
- name取得

#### フォールバック
- ディレクトリ名使用

---

### 4.3 アイコン取得（重要）

#### 優先順位（フォールバック）
1. Google Profile Picture.png
2. Google Profile.ico（上記PNGがない場合）
※いずれも見つからない場合はアイコンを表示しない（空白）。chrome.exeのアイコンは使用しない。

#### キャッシュ
- `%TEMP%\\ChromeProfileLauncher\\icons`
- 更新日時で再生成

---

### 4.4 ランチャ機能

#### 動作
- 起動済 → フォーカス
- 未起動 → 起動

#### 起動コマンド
```
chrome.exe --profile-directory="Profile X"
```

---

### 4.5 起動状態判定（改良）

#### 方法
- **LOCK判定**: 各プロファイルディレクトリ内の `SingletonLock` ファイルの有無をOSレベルで確認し、起動状態を一次判定する。
- **ウィンドウ・プロセス差分検出**: 起動直前と直後のスナップショットを比較し、新規に増えたウィンドウ/プロセスを当該プロファイルに紐付ける。これにより、Chromeのプロセス集約問題（既存プロセスへの吸収）が発生しても確実に特定が可能。
- **動的生存監視**: 紐付けられたウィンドウハンドル（hwnd）の有効性を定期的に確認し、終了を検知する。

---

### 4.6 フォーカス制御

- Win32 API (`SetForegroundWindow`, `ShowWindow`, `BringWindowToTop`)
- **確実な最前面化**: `AttachThreadInput` を用いてフォアグラウンドスレッドにアタッチし、Windowsの制限を回避して確実にウィンドウを前面へ移動させる。
- **ウィンドウクラス名判定**: `Chrome_WidgetWin_1` およびプロセス名 `chrome` を確認し、Electron系アプリ（Slack、VS Code、Discord等）が同一クラス名を使用する問題を回避。

---

### 4.7 設定機能

- 並び替え（ドラッグハンドルを使用した直感的なドラッグ＆ドロップ）
- 表示／非表示（トグルスイッチによる切り替え）
- プロファイルフォルダ名を表示（プロファイル名の下に表示）
- プロファイルフォルダを開く機能（「OPEN」ボタン）
- ※プロファイル名およびアイコンの編集機能（独自の画像指定など）は提供しない

## 5. UI仕様

### 5.1 ランチャ画面

- タイトルバーなしのコンパクト表示（「Chrome Launcher」等のタイトル表示は廃止）
- 縦リスト表示（ダークテーマ採用のカード形式デザイン。カード背景色は視認性向上のため #222222 を採用）
- アイコン + 名前（左揃えレイアウト、文字色は白 #FFFFFF に固定）
- スムーズスクロール対応（ピクセル単位の滑らかなスクロール）
- 設定画面表示中はメイン画面全体をグレーアウト（半透明レイアウトを表示）
- 右下に設定ボタンを配置

---

### 5.2 設定画面

- 別ウィンドウ（ShowDialog）
- スムーズスクロール対応
- ドラッグハンドルによる並び替え（ドラッグ中のドロップ先アイテムを半透明化する視覚的フィードバック付き）
- トグルスイッチ（表示／非表示）
- プロファイルフォルダを開くボタン
- プロファイル名およびフォルダ名の表示（読み取り専用）
- 不要なラベル（「NAVIGATION MODULES」等）を排除したシンプルな構成


## 7. 処理フロー

### 起動時
1. プロファイル取得
2. 設定読込
3. データマージ（Chrome側プロファイルをベースとし、設定があれば上書き、なければデフォルト追加）
4. アイコンキャッシュ確認
5. UI生成

### 操作時
1. **状態確認**: `SingletonLock` の存在を確認。
2. **フォーカス**: 起動中の場合、管理下の `hwnd` が有効であればフォーカス。無効であればタイトルマッチ等で再探索してフォーカス。
3. **バックアップ**: ウィンドウが見つからない場合は「未起動」として扱う。
4. **起動**: プロセス起動直前にウィンドウ一覧のスナップショットを取得。
5. **プロセス実行**: `--profile-directory` 指定での起動。
6. **紐付け**: 出現した新規ウィンドウ/プロセスを `hwnd` として記録。

## 13. 制約

- **Chrome仕様依存**: LOCKファイルの存在、プロセス集約の挙動、ウィンドウクラス名 (`Chrome_WidgetWin_1`) など、Chromeの内部実装に依存する。アップデートにより変更される可能性がある。
- **外部起動の制限**: ランチャ外から起動されたプロファイルウィンドウは、差分検出では捕捉できない（タイトルマッチでのフォールバックは可能）。
- **AUMIDの制限**: AUMIDは全プロファイルで共通のため、プロファイル識別には使用不可。
