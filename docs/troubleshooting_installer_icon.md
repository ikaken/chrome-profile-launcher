# トラブルシューティング記録: インストーラーアイコン反映の不具合

## 概要
GitHub Actions (Velopack) を用いた自動リリースにおいて、`setup.iss` を手動修正してもインストーラーのアイコンが本番環境で反映されない問題が発生した。

## 原因
1. **GitHub Actions のビルド環境**: Actions 環境はリポジトリのコードのみを参照し、手動でビルドした `setup.iss` やローカルのキャッシュは無視される。
2. **Velopack の仕様**: Velopack は独自のパッケージング方式を採用しており、`setup.iss` を使用せず、`vpk pack` コマンドで構成を決定する。
3. **Windows アイコンキャッシュ**: 本番環境で確認した際、OS がインストーラー実行ファイルのアイコンを以前のままキャッシュしており、更新が反映されていないように見えた。

## 解決策
1. **ワークフロー修正**: `.github/workflows/release.yml` の `vpk pack` コマンドに `--icon` オプションを追加し、ビルド時に正しいアイコンを明示的に指定するようにした。
2. **リリース管理**: 同一バージョン番号でのアセット上書きはキャッシュ問題を引き起こしやすいため、トラブル時はバージョンをインクリメント（例: v0.1.5 -> v0.1.6）して再デプロイする。
3. **確認手順**: アイコンの更新確認時は、ファイル名をリネームするか、別の場所に移動して OS のキャッシュを回避する。

## 今後の教訓
- 自動パッケージング環境（CI/CD）を利用している場合、手動ビルド用の設定（`setup.iss`）と CI 上の設定は分けるか、統合する必要がある。
- アイコン変更のようなメタ情報の更新は、CI パイプライン内でパラメータとして渡すのが最も確実である。
