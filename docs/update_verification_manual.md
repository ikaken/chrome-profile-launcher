# アップデート機能 検証手順書（テスト用）

本番環境（あるいは検証環境）にて、自動アップデート機能が正しく動作するかを確認するためのテスト手順です。

## 1. 事前準備
- GitHub リポジトリへのアクセス権限があること。
- GitHub Actions の `Release` ワークフローが正しく設定されていること。

## 2. 検証の手順

### Step 1: 旧バージョンのインストール
1. GitHub Releases にて、あらかじめ公開されている「旧バージョン（v0.1.3-betaなど）」のセットアップファイル（`ChromeProfileLauncherSetup.exe`）をダウンロードし、インストールします。
2. アプリを起動し、正常に動作することを確認します。

### Step 2: テスト用バージョンの発行
1. ローカルコード（`feature/016-auto-update` ブランチ）を `main` にマージします。
2. 新しいバージョンとしてタグを作成します。
   ```powershell
   # 例: v0.1.4-test を発行
   git tag v0.1.4-test
   git push origin v0.1.4-test
   ```

### Step 3: CI/CDの確認
1. GitHub の [Actions] タブを開き、`Release` ワークフローが成功するまで待ちます。
2. [Releases] ページに `v0.1.4-test` が作成され、アセット（Setup.exe 等）が添付されていることを確認します。

### Step 4: アップデートの検知
1. Step 1 でインストールした旧バージョンのアプリを起動します。
2. 起動から 3 秒待機し、アップデート通知のダイアログが表示されるか確認します。
3. 表示されない場合は、設定画面を開き「アップデートを確認」ボタンをクリックして手動チェックを試みます。

### Step 5: アップデートの適用
1. 「新しいバージョンが利用可能です」のダイアログで「はい」を選択します。
2. ダウンロード完了後、再起動の確認ダイアログで「はい」を選択します。
3. アプリが一度終了し、自動的に新しいバージョンとして起動することを確認します。

### Step 6: 完了確認
1. アプリが起動したら、設定画面を開きます。
2. 表示されているバージョン番号が `0.1.4-test` になっていること、または最新のビルドであることを確認します。

---

## ⚠️ トラブルシューティング
- **アップデートが検知されない**: 
  - `RELEASES` ファイルが GitHub Releases に存在するか確認してください。
  - アプリのログファイル（`%APPDATA%\\ChromeProfileLauncher\\logs\\`）を確認し、通信エラーが出ていないか確認してください。
- **再起動が失敗する**: 
  - インストールディレクトリのパーミッションや、他のプロセスによるロックがないか確認してください。

## テスト終了後
- 検証のために作成したテスト用タグ（`v0.1.4-test`）は、必要に応じて GitHub 上で削除してください。
