# Chromeプロファイルランチャ テスト仕様書

## 1. はじめに
本ドキュメントは、Chromeプロファイルランチャの品質を保証するためのテスト項目と実施方法を定義する。
テストは「自動テスト（Unit Test）」と「手動テスト」の2段階で構成される。

---

## 3. 結合・手動テスト (Manual Tests)
UI操作やOSとの連携が必要な機能について、手動でテストを実施する。

### 3.1 起動・フォーカス機能
- [ ] **新規起動**: プロファイル一覧からボタンを押し、対象プロファイルのChromeウィンドウが新しく開くこと。
- [ ] **表示確認 (メイン)**: 各プロファイルの表示名のみが表示され、フォルダ名（Default等）が表示されていないこと。
- [ ] **フォーカス（基本）**: 単一のプロファイルが起動している際、ボタン押下で最前面に表示されること。
- [ ] **フォーカス（プロセス集約）**: 既に `Default` 等の別プロファイルが起動しており、プロセスが集約されている状態でも、対象プロファイルのウィンドウが正しく識別・フォーカスされること。
- [ ] **ウィンドウ差分検出の正確性**: Chrome起動直前のスナップショットに含まれない新規ウィンドウのみが、正しく現在のプロファイルに紐付けられること。
- [ ] **差分検出失敗時のフォールバック**: 既存プロセスに吸収される等で新規ウィンドウが検出できなかった場合、タイムアウト後にタイトルマッチ等の代替手段で試行されること。
- [ ] **タイムアウト動作**: 差分検出のポーリングがタイムアウトした場合に、アプリがフリーズせず適切なログが出力されること。
- [ ] **LOCKファイル判定**: `SingletonLock` が存在するプロファイルに対して、新規プロセスを不要に生成せず、即座に既存ウィンドウを探索すること。
- [ ] **LOCKファイル異常残存**: Chromeが異常終了して`SingletonLock`が残っている場合、「起動中」と誤判定した後にウィンドウが見つからない場合、適切に新規起動にフォールバックすること。
- [ ] **外部起動ウィンドウ**: ランチャ以外の方法（デスクトップショートカット等）で起動されたプロファイルウィンドウに対して、タイトルマッチによるフォーカスが機能すること。
- [ ] **ウィンドウクラス名判定**: `Chrome_WidgetWin_1` を使用するElectron系アプリ（Slack、VS Code等）が起動している状態で、Chromeウィンドウのみが正しく検出されること。
- [ ] **エラーハンドリング**: Chromeがインストールされていない環境で、適切なエラーメッセージが表示されること。
- [ ] **タイトルの非表示**: メイン画面に「Chrome Launcher」等の不要なタイトルが表示されていないこと（コンパクトレイアウト）。
- [ ] **視認性の確認**: カード背景色（#222222）と白文字（#FFFFFF）の組み合わせで、文字が明瞭に読めること。
- [ ] **スムーズスクロール**: マウスホイール操作時に、アイテム単位ではなくピクセル単位で滑らかにスクロールすること。

### 3.2 アイコン表示
- [ ] **優先順位確認**: 
    1. `Google Profile Picture.png` があればそれを表示。
    2. なければ `Google Profile.ico` を表示。
    3. いずれもなければアイコンは表示しない（空白）。
- [ ] **キャッシュ不要の確認**: プロファイルディレクトリ内の画像が直接読み込まれること。

### 3.3 設定画面と並び替え
- [ ] **ドラッグ＆ドロップ**: 設定画面でプロファイル左側のハンドル (`☰`) をドラッグして順序を入れ替え、メイン画面に反映されること。
- [ ] **プロファイルフォルダを開く**: 「OPEN」ボタンを押し、対象のプロファイルディレクトリがエクスプローラで正しく開くこと。
- [ ] **表示確認 (設定)**: 表示名の下に正確なフォルダ名（`/Default` 等）が表示されていること。
- [ ] **グレーアウト動作**: 設定画面を開いている間、メイン画面が半透明のレイヤー（Dimmer）で覆われ、背面が操作不可に見えること（視覚的フィードバック）。
- [ ] **表示/非表示**: 非表示に設定したプロファイルが、メイン画面の一覧から消えること。
- [ ] **保存**: アプリを再起動しても、並び替え順や表示設定が保持されていること。
- [ ] **ドラッグ中フィードバック**: 並び替えのドラッグ中に、ドロップ先となるアイテムが半透明（Opacity 0.4）になり、挿入位置が視覚的に分かること。
- [ ] **ラベルの排除**: 設定画面に「NAVIGATION MODULES」等の不要なラベルが表示されていないこと。

### 3.4 ウィンドウ位置・サイズの記憶・復元 【未実装】
- [ ] **位置の保存と復元**: ウィンドウを任意の位置に移動・リサイズして閉じた後、再起動で前回の位置・サイズに表示されること。
- [ ] **初回起動**: 設定ファイルが存在しない初回起動時に、デフォルトサイズ（420×500）で画面中央に表示されること。
- [ ] **最大化状態での終了**: ウィンドウを最大化した状態で閉じた後、再起動で前回の通常状態（最大化前）の位置・サイズで復元されること。
- [ ] **最小化状態での終了**: ウィンドウを最小化した状態で閉じた後、再起動で前回の通常状態の位置・サイズで復元されること。
- [ ] **モニター構成変更**: 外部モニターにウィンドウを配置して閉じた後、外部モニターを切断してから再起動した場合、画面中央にフォールバックすること。
- [ ] **範囲外座標の手動設定**: `settings.json` を手動編集してスクリーン外の座標を設定した場合、起動時に画面中央にフォールバックすること。
- [ ] **極小サイズの手動設定**: `settings.json` を手動編集してサイズを最小閾値未満（例: Width=50, Height=50）に設定した場合、起動時にデフォルトサイズにフォールバックすること。
- [ ] **設定保存との非干渉**: 設定画面を開いてプロファイルを保存した後、`settings.json` 内のウィンドウ位置データが消失していないこと。

### 3.5 単一インスタンス（二重起動防止）
- [ ] **二重起動の防止**: アプリが既に起動している状態で、再度アプリを起動しようとした際、新しいプロセスが即座に終了すること。
- [ ] **既存ウィンドウの活性化**: 二重起動を試みた際、既に起動していたメインウィンドウが最前面に表示されること。
- [ ] **最小化からの復帰**: メインウィンドウが最小化されている状態で二重起動を試みた際、ウィンドウが元のサイズ（Normal）に戻り、かつ最前面に表示されること。

## 4. テスト環境
- **OS**: Windows 10 / 11
- **対象ブラウザ**: Google Chrome (最新版推奨)
- **ビルド環境**: .NET 10.0 SDK

## 5. テスト実行手順
1. **自動テスト**: 
   ```bash
   dotnet test
   ```
2. **手動テスト**: 
   - `dotnet run` でアプリを起動し、3. のテスト項目を順次実施する。
