# リリース作業マニュアル

このドキュメントでは、Chrome Profile Launcher の新バージョンをリリース（公開）する際の手順について説明します。
自動アップデート機能（Velopack）と GitHub Actions の導入により、リリースの大部分は自動化されています。

## 1. リリース前の準備

### 1.1 バージョン番号の決定
[セマンティック バージョニング](https://semver.org/lang/ja/)（例: `1.2.3`）に従って、次のバージョン番号を決定します。

### 1.2 ローカルでの最終確認
リリース対象のブランチ（通常は `main`）で、ビルドとテストが通ることを確認します。

```powershell
dotnet test
dotnet build -c Release
```

## 2. リリースの実行（タグのプッシュ）

GitHub Actions は、`v` で始まるタグがプッシュされたことを検知して自動的にリリース処理を開始します。

### 2.1 Git タグの作成
決定したバージョン番号に `v` を付けてタグを作成します。

```powershell
# 例: バージョン 1.0.0 をリリースする場合
git tag v1.0.0
```

### 2.2 タグのプッシュ
作成したタグを GitHub リモートリポジトリにプッシュします。

```powershell
git push origin v1.0.0
```

## 3. 自動処理の監視（GitHub Actions）

タグをプッシュすると、GitHub リポジトリの **[Actions]** タブで `Release` ワークフローが開始されます。

1.  GitHub のリポジトリページを開きます。
2.  **[Actions]** タブをクリックします。
3.  進行中の `Release` ワークフローを選択し、エラーなく完了するのを見守ります（通常 3〜5 分程度）。

## 4. リリースノートの編集

ワークフローが完了すると、**[Releases]** ページに新しいドラフトまたは公開済みリリースが作成されます。

1.  リポジトリ右側の **[Releases]** をクリックします。
2.  作成されたタグを選択し、**[Edit release]** をクリックします。
3.  **Release title** を設定します（例: `v1.0.0 - 〇〇機能の追加`）。
4.  **Description**（リリースノート）に、今回の変更点や修正内容を記載します。
5.  **[Publish release]** をクリックして確定させます。

## 5. 自動アップデートの確認

リリースが完了すると、既にアプリをインストールしているユーザーには、次回の起動時（または起動中のチェックタイミング）にアップデート通知が表示されます。

*   **通知のタイミング**: アプリ起動の 3 秒後にチェックが行われます。
*   **確認事項**: 自身の環境でアプリを起動し、「新しいバージョンが利用可能です」というダイアログが表示され、正常に更新・再起動ができるかを確認してください。

---

## ⚠️ 注意事項
*   **タグの重複禁止**: 一度プッシュしたタグは削除したり再利用したりしないでください。Velopack の整合性が壊れる可能性があります。
*   **ビルドエラー時の対応**: GitHub Actions でエラーが発生した場合は、アセットが不完全な状態でリリースされている可能性があります。Actions のログを確認し、問題を修正した上で、新しいバージョン番号（パッチバージョンを上げたもの）で再度リリースをやり直してください。
