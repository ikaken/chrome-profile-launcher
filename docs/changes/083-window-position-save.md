# タスクトレイ常駐が有効な場合にウィンドウ位置が保存されない

Issue: https://github.com/ikaken/chrome-profile-launcher/issues/83

## 背景 / 目的
タスクトレイ常駐（`EnableTaskTray=true`）が有効な場合、メインウィンドウの位置・サイズを変更しても
次回起動時に復元されず、常にデフォルト位置で開く。

### 根本原因
ウィンドウ位置を保存するコードは `MainWindow.Window_Closing` の 1 箇所のみだが、常駐が有効な場合は
`SaveWindowPosition` に到達する前に `e.Cancel = true` で早期 return している（トレイ常駐機能の導入時
`ba4550f` から存在する不具合）。またトレイメニューの「終了」も Shutdown 時に同じ分岐で return するため、
常駐が有効な限りウィンドウ位置が保存される経路が存在しない。

## 変更内容
- `MainWindow.xaml.cs` `Window_Closing`:
  - 常駐判定の**前に**ウィンドウ位置の保存処理を移動し、トレイに格納する場合・実際に終了する場合の
    双方で保存されるようにする。
  - 保存する位置は `Left/Top/Width/Height` ではなく `RestoreBounds` を使用し、最大化中に閉じた場合に
    最大化時のスクリーン座標が誤って保存される問題を同時に修正する。
    （`RestoreBounds` は Normal/Maximized/Minimized のいずれの状態でも通常時の矩形を返す）
- テスト: ウィンドウコードビハインドのため自動テストは追加せず、手動動作確認で担保する。

## 影響範囲
- `MainWindow.Window_Closing`
- ユーザーへの影響:
  - 常駐有効時にも、ウィンドウを閉じた（トレイに格納した）時点で位置・サイズが保存され、
    次回起動・再表示時に復元される。
  - 最大化中に終了した場合、通常時の位置・サイズが保存され `IsMaximized=true` が記録される
    （従来は最大化中の座標がそのまま保存されていた）。
  - 常駐無効時の挙動は変わらない（従来通り保存される）。

## 備考
- `ExitApplicationCommand`（トレイの「終了」）側への保存処理追加は不要。
  `Application.Current.Shutdown()` 時に `Window_Closing` が発火し、本修正により常駐分岐の前に
  保存されるため、1 箇所の修正で両経路をカバーできる。
- 最小化状態で終了した場合は `RestoreBounds` により正しい通常時矩形が保存される。
- 保存タイミングは「閉じた/トレイに格納した時点」であり、ウィンドウを移動しただけでは即時保存されない
  （移動後にプロセスが異常終了した場合は位置が失われる）。より確実にするには `LocationChanged` /
  `SizeChanged` での保存も検討できるが、頻度と複雑さの兼ね合いから今回は対象外とする。
