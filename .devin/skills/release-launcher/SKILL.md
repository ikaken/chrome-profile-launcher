# Release Launcher

## 前提
`v*` タグをプッシュすると GitHub Actions が起動し、インストーラーのビルド・パッケージング・リリース作成を自動実行する。

## フロー
1. **事前準備**: `git status` でクリーンを確認。バージョンルールに基づいてバージョンを決定する（例: `v0.1.5-beta`）。
2. **タグ付け**: `git tag <バージョン番号>`。
3. **プッシュ**: `git push origin <バージョン番号>`。
4. **アクション監視**: GitHub Actions の完了とインストーラー生成を確認する。
5. **README更新**: `README.md` のダウンロードリンクとバージョン表記を更新し、コミット・プッシュする。
6. **リリースノート編集**: GitHub上でリリース詳細を編集する。

## バージョンルール

プロジェクトは `v{major}.{minor}.{patch}-beta` 形式のセマンティック バージョニングを採用する。

| 位置 | 名前 | 変更条件 |
|---|---|---|
| 1番目 | **major** | ユーザーが明示的に指示した時のみ変更する。 |
| 2番目 | **minor** | 機能追加（`enhancement` タグ）の Issue に対応した時に変更する。minor が上がった場合、patch は `0` にリセットする。 |
| 3番目 | **patch** | バグ対応（`bug` タグ）の Issue に対応した時に変更する。 |

### 例
- 現在 `v0.1.16-beta` で、機能追加の Issue を対応した場合 → `v0.2.0-beta`
- 現在 `v0.1.16-beta` で、バグ対応の Issue を対応した場合 → `v0.1.17-beta`

## 注意事項
- 手動ビルドは不要。Actions が最新ソースをベースにパッケージングする。
- リリース前に `main` が最新状態であることを確認する。
- `main` ブランチへの変更はユーザー承認を得てから行う。
