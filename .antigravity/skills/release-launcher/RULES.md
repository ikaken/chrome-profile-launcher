# Release Launcher: Rules & Prerequisites

本プロジェクトを安全かつ確実にリリースするための基本ルールと前提条件を定義します。

## 🛑 基本原則（絶対に守ること）

1. **プッシュ前の承認必須**:
   * `main` ブランチへのすべてのプッシュ（README更新等）は、直前に変更予定内容をユーザーに提示し、明示的な承認を得ること。（`GEMINI.md` に定められた厳格なルールです）

2. **タグの重複禁止**:
   * 一度作成・プッシュしたバージョンタグ（例: `v1.0.0`）は削除したり再利用したりしないこと。
   * これを破ると、Velopackのリリースキャッシュや自動アップデート整合性が破壊されます。

3. **ビルドエラー時の対応**:
   * GitHub Actionsでのリリースビルドでエラーが発生した場合、アセットを上書きするのではなく、必ずバージョンをインクリメント（パッチバージョン等をバンプ、例: `v1.0.1`）した新しいタグでリリースをやり直すこと。

4. **手動ビルドの排除**:
   * 配布用の公式インストーラーは手動ビルド（Inno Setupのローカル実行など）せず、必ず GitHub Actions 経由で生成されたアセットを使用すること。

---

## 🛠 前提環境（Prerequisites）

リリース作業を開始する前に、以下の環境が整っていることを確認してください。

1. **Git / GitHub CLI (`gh`)**
   * リモートリポジトリ（origin）へのタグのプッシュ権限があること。
   * `gh auth status` で GitHub CLI が認証済みであること（Actionsの監視やリリースノートの編集に使用します）。

2. **.NET 10.0 SDK**
   * リリース前の最終確認としてのローカルビルド・テスト実行（`dotnet test`）のために必要です。
