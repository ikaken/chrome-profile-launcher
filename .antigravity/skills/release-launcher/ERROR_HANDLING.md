# Release Launcher: Error Handling & Troubleshooting

リリース作業の進行中に問題が発生した場合は、以下の対処方針に基づいて処理を行い、リリース品質を維持してください。

## ⚠️ エラーハンドリング・マトリクス

| 状況 | エラー内容・事象 | 具体的な対応 |
|---|---|---|
| **Step 0** | ローカルでのテスト（`dotnet test`）が失敗する | テスト失敗の原因となったコードやアサーションを特定します。修正可能な範囲であれば修正を行いますが、時間がかかる場合は**リリースプロセスを直ちに中断**し、ユーザーに報告します。 |
| **Step 2** | `git push origin vX.Y.Z` が失敗する | リモートへのアクセス権限や、タグの競合状況をチェックします。すでに同じタグが存在する場合は、タグの削除や上書きを行わず、バージョン番号を変更（インクリメント）した新規タグで再試行を提案します。 |
| **Step 3** | GitHub Actionsのビルド・リリースジョブがエラーになる | 1. ワークフローログ（エラー箇所）を確認し、原因（アセット不足、証明書エラー、ネットワーク切断等）を特定します。<br>2. 原因を解消後、**必ずバージョンをインクリメント（例: vX.Y.Z から vX.Y.Z+1）した新規タグ**を作成し、`Step 0` からリリースフローをやり直します。※アセットの無理な手動上書きは禁止。 |
| **共通** | ユーザーからのリリース差し戻し | ユーザーから指摘された懸念点やバグ修正を行い、再度 `Step 0` からリリースフローを再開します。 |

## 📌 過去のトラブルシューティング対応履歴（ナレッジ）

### 事象：インストーラーアプリアイコンが反映されない（Issue #23）
* **原因**: 
  GitHub Actionsのビルド環境（Ubuntuなど）でVelopackのパッケージング（`vpk pack`）を実行する際、インストーラー用アイコンファイル（`--icon`）がビルドパイプラインのパラメータで明示的に指定されていなかったため、キャッシュ等の影響で古い、あるいはデフォルトのアイコンが残ってしまっていました。
* **恒久対策**: 
  `.github/workflows/release.yml` 内の `vpk pack` コマンドライン実行時に、明示的に `--icon ./Assets/setup-icon.ico` を指定する形でビルド定義を修正。
* **運用ルール**: 
  アセットの修正反映を確実にするため、同一バージョンタグでのアセット上書きではなく、バージョンインクリメントによる再リリースを徹底します。
