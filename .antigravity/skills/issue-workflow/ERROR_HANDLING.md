# Issue Handling: Error Handling & Policies

ステップ実行中に問題が発生した場合、エージェントは以下のルールに従って迅速かつ適切に対処してください。

## ⚠️ エラーハンドリング・マトリクス

| 発生状況 | エラー事象 | 具体的な対応 |
|---|---|---|
| **Step 0** | 環境チェックの失敗（Git未設定、gh未認証等） | ユーザーに不足している設定やツールの導入手順を案内し、**スキルを一時中断**します。 |
| **Step 5** | ビルドエラーの発生 | エラー内容（コンパイルエラーなど）を分析し、修正を試みます。**最大3回**試行しても解決しない場合は、詳細ログを添えてユーザーに報告し指示を仰ぎます。 |
| **Step 8** | テストの失敗 | 失敗したテストの原因を分析し修正を試みます。テスト自体の仕様変更や前提条件のズレが生じている場合は、速やかにユーザーに確認します。 |
| **Step 10-11** | Push または PR 作成の失敗 | 認証エラーやネットワーク問題を切り分け、ユーザーに報告します。GitHub CLIが利用できない場合は、ブラウザ経由の手動操作手順をわかりやすく案内します。 |
| **共通** | クォータ制限エラー (`429 Too Many Requests` 等) | **即座に作業を中断**します。ユーザーに対し、現在の「完了したステップ」と「未完了のタスク」を簡潔に報告し、「API制限のため、一時的に一般モデル（Generalistなど）へ作業を切り替えますか？」と提案し、指示を仰ぎます。 |
| **共通** | ユーザーからの手動中断指示 | 現在の作業状態を `docs/changes/` にすべて記録し、進行中のコードやドキュメントを途中経過コミットした上で、安全に作業を中断します。 |
