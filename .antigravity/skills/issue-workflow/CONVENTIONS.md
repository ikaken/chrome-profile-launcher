# Issue Handling: Conventions & Templates

本プロジェクトで Issue 対応を行う際の共通規約です。すべてを厳密に守って作業を進めてください。

## 🌿 ブランチ命名規則
* **形式**: `feature/{Issue番号}-{内容の英単語}`
* **例**: `feature/012-profile-sort`

---

## 📝 変更履歴（changes）ドキュメント
* **配置フォルダ**: `docs/changes/`
* **ファイル名**: `{issue番号}-{内容の英単語}.md`
* **初期化テンプレート**:
  ```markdown
  # {Issueタイトル}

  ## 背景
  {なぜこの変更が必要なのか、何を解決するのか}

  ## 目的
  {この変更によって達成される状態}

  ## 変更内容
  - {変更点1}
  - {変更点2}

  ## 影響範囲
  - {修正したクラス/メソッド/ファイル}
  - {ユーザー動作への影響}

  ## 非対応
  {今回の対応対象外とした事項}

  ## 備考
  {設計上の判断、トレードオフ、未対応事項など}
  ```

---

## 💾 コミットメッセージ規約
* **形式**: `{prefix}: {日本語での変更内容}`
* **Prefix一覧**:
  - `feat` : 機能追加
  - `fix` : バグ修正
  - `refactor` : リファクタリング（機能の整理・クリーンアップ）
  - `docs` : ドキュメントの変更
  - `test` : テストコードの追加・修正

---

## 🔗 Pull Request 概要テンプレート
PR作成時（Step 11）は、以下の項目を概要（Description）に含めてください。
* **必須要素**:
  - `Fixes #{Issue番号}` （GitHubのIssue自動クローズ用）
  - `docs/changes/{changesファイル名}.md` へのファイル絶対パスまたは相対リンク
  - 変更概要（日本語）
  - 動作検証およびテスト実行結果のサマリー
