# Issue Handling: Workload Optimization Guidelines

Antigravityは単一の強力なAIエージェントですが、大規模な調査や並行処理、コンテキスト肥大化の防止のために、内蔵されたサブエージェントを動的に定義・起動して作業を分散させることができます。

## 1. 🔍 調査フェーズでの分散（Step 1）
* **手法**: `research` サブエージェントを起動して並行調査を依頼する。
* **役割**: ソースコードの広範囲な探索や複数ファイルの読み込みなど、情報収集に特化。
* **メリット**: メインエージェントの会話コンテキスト（トークン）が大量のコード読み取りで肥大化するのを防ぎ、スマートな計画設計（`implementation_plan.md`）に集中できます。

## 2. 💻 実装および検証フェーズでの分散（Step 5, 8）
* **手法**: `self` または `define_subagent` で特定の役割を持たせたサブエージェントを定義・起動する。
* **役割**: 大規模なリファクタリング、複数コンポーネントの書き換え、または長時間のテスト実行をバックグラウンド処理。
* **メリット**: サブエージェントが裏で正確に実装を進め、メインエージェントは進捗管理（`task.md` の更新）とユーザーとの対話に専念することで、全体の応答性と安定性を向上させます。

## 3. 📝 ドキュメント・定型作業の分散（Step 9, 12）
* **手法**: 専用のサブエージェント（例: `doc-assistant`）を起動する。
* **役割**: 実装完了後の大量のマークダウン仕様書・設計書・テスト仕様書の同期、PR作成後のローカルブランチ削除やマージ後クリーンアップなどの定型作業の実行。
* **メリット**: 単調で量の多いファイル書き換え作業を一括で任せることができ、メインエージェントの処理リソースを最適に保ちます。
